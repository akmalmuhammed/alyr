# Content Design System

## Product voice

Direct, calm and useful. The interface should sound like an experienced operator who knows the context and respects the user's time.

## Labels

- Use verbs for actions: `Review proposal`, `Upload documents`, `Approve changes`.
- Use nouns for destinations: `Projects`, `Evidence`, `Roadmap`, `Settings`.
- Avoid vague verbs: `Proceed`, `Submit`, `Manage` when a specific action is available.

## Status language

Use a consistent lifecycle:

- `Not started`
- `In progress`
- `Waiting for you`
- `Waiting for ALYR`
- `At risk`
- `Complete`
- `Archived`

Avoid internal workflow codes in client-facing views.

## Dates and time

- Use absolute dates for commitments: `15 July 2026`.
- Use relative time only for recent activity: `12 minutes ago`.
- Include Qatar time zone when coordinating across markets: `14:00 AST (Qatar)`.

## Numbers

- Use tabular figures in metrics and tables.
- Include currency: `QAR 48,500`.
- Label estimates: `Estimated annual saving`.
- Avoid false precision in forecasts.

## Empty state formula

1. Name what belongs here.
2. Explain why it matters.
3. Offer the best first action.

Example: “No evidence added yet. Upload a process file or connect a system so the audit team can map the current workflow.”

## Error formula

1. What failed.
2. What was preserved.
3. How to recover.
4. Human support route when necessary.

## AI language

Use `AI-assisted`, `suggested`, `drafted` or `extracted`. Do not use `verified`, `approved` or `complete` until the relevant human/system validation has occurred.
