# Release and Approval Process

## Roles

- Brand owner approves identity, positioning and public claims.
- Design lead approves new components, icons, templates and campaign systems.
- Product/engineering owns implementation and accessibility QA.
- Delivery lead owns client handoff, source links and changelog.

## Required before release

- source file and export linked
- correct approved master asset
- English and Arabic copy reviewed
- responsive and RTL check completed
- accessibility/focus/contrast check completed
- no secret, customer data or unapproved claim committed
- change recorded in the design-system changelog

## Versioning

- MAJOR: identity, logo geometry, palette roles or typography change
- MINOR: new component, asset family or template
- PATCH: correction, copy fix or export regeneration

## Commit convention

`brand:` identity and asset work
`ux:` UX, content and interaction rules
`build:` application implementation
`docs:` strategy, handoff and governance
`qa:` validation or release evidence
