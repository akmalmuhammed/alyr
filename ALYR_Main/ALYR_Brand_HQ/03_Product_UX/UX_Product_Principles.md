# ALYR Product and UX Principles

## Experience model

ALYR interfaces should feel like calm command systems: outcome-led, structured, premium and operationally clear.

## Product flow

1. Orient: show the business outcome and current state.
2. Diagnose: expose evidence, friction, risk and opportunity.
3. Decide: present the next meaningful decision with owner and trade-off.
4. Execute: make the workflow, handoff and status explicit.
5. Measure: show the KPI movement and evidence boundary.
6. Improve: turn learnings into the next prioritized action.

## Component rules

- one primary action per decision area
- use Carbon for command/focus and Paper/White for analysis
- use Volt only for state or action
- use IBM Plex Mono for IDs, timestamps, status and technical metadata
- use logical CSS properties for RTL
- include loading, empty, partial, stale, error, offline and success states
- show human approval when AI-assisted output affects customers, documents or compliance

## Responsive and bilingual QA

Test at 320, 768, 1024 and 1440px. Test Arabic independently: navigation order, arrows, mixed-script IDs, line wrapping, tables and forms. Respect reduced motion and visible keyboard focus.

## Shared digital building blocks

- audit workspace
- opportunity backlog
- customer journey map
- CRM pipeline
- service/case timeline
- document vault
- task and ownership panel
- KPI command center
- approval and audit trail
- notification and follow-up engine
