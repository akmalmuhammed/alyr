# Audit, 17 October 2026: hygiene, security and readiness before go-live

Linear ALY-114. Scope: the repository on `main` (dd66fce), the open pull requests, the founder's
laptop environment and what is reachable on the internet. Method: three independent reviews
(docs and governance; security and operations; code, tests and repository) plus live checks.
Each finding has a status: **Fixed** (in the ALY-114 pull request), **Issue** (with its number),
or **Founder** (needs the founder's decision or account).

## Summary

The core is sound: tenant isolation is enforced by the database and tested on every change,
consent and the 24-hour window are enforced in one place, no secrets are in git, both
dependency trees have no known vulnerabilities, and all 377 API tests pass. The weak points
were settings that failed open, missing governance and operations documents, docs that drift
because many sessions write them, and nothing yet for monitoring, rate limits, retention or
privacy notices. This audit fixes the first two and turns the rest into tracked issues.

## What keeps this from happening again
- `docs/hygiene.md`: where everything lives, what each change includes, how docs stay true.
- The PR template's checklist, CODEOWNERS on the risky paths, CI audits, Dependabot, and a
  hook that blocks secrets and personal documents and is turned on by `scripts/check.sh`.
- `docs/runbooks/go-live-checklist.md` gates the first real customer.
- Weekly review (operator agent) and a full audit before go-live and every quarter.
