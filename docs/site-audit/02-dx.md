# Site audit 02: developer experience

**Scope:** how easy and safe it is for a person or a coding agent to change the public site.
**Read on:** `D:\alyr-home`, branch `aly-shelf-documents-pages` (PR #102), 24 Oct 2026.
**Method:** read-only.
- One timed `next build` into a throwaway `distDir`; `tsc`, `lint` and `design-check` timed.
- EN/AR parity and banned-word scans, from a scratch script run on the compiled copy.
- In-memory trial merges (`git merge-tree`) and `curl` of the live site.

No code changed. The build rewrote `apps/web/tsconfig.json`; that was reverted.

## Summary

The code is careful. Copy is typed, tokens are generated and drift-checked, the
post-processing fails loudly, and the skills are thorough. The weak part is around the code:
- what is live cannot be traced to a commit;
- CI gates nothing;
- the build that ships never runs in CI;
- the key checks (screens, axe, Lighthouse, 320 px) run from `docs/` or from folders
  outside the repo.

## P0

### P0-1 What is live cannot be traced to a commit, and the documented rollback does not work

**#105 is live, not #102.**
- The live H1 reads "The tech team your business never had." That line exists only on
  `origin/aly-210-tech-team-homepage` (PR #105). It is not in #102 or `main`.
- #105 tops a stack of four open site PRs, each containing the one below:

| PR | Commits ahead of `main` |
|---|---|
| #102 | 13 |
| #103 | 16 |
| #104 | 20 |
| #105 | 22 |

**The local build is not the live build.** The local `out-site` (21 Oct) loads different
chunk hashes from the live site (`3w299…` against `1l381…`).

**The documented rollback cannot work.**
- The documented rollback is "redeploy the previous `out-site`"
  (`alyr-design-review/SKILL.md:102`). But `build-site.sh:17` deletes `out-site`, and
  nothing archives it.
- The output has no commit stamp.
- `wrangler rollback` is documented nowhere.

**Fix:**
- Write the SHA into `out-site/version.txt` and a `<meta>` tag.
- Deploy only pushed commits.
- Document `wrangler versions list` and `wrangler rollback`.

**Effort:** S. Deploying from CI is M (P1-5).

### P0-2 CI gates nothing
- All 10 open PRs fail every job in 4–5 s. That is billing, not the code.
- Nothing has merged since #94, so site work stacks on unreviewed work.
- `scripts/check.sh` needs Postgres, and nothing records that it ran.

**Fix:**
- Unblock Actions: billing, a public repo, or a self-hosted runner.
- Meanwhile, add a DB-free `pnpm site:check` whose output is pasted into each PR.

**Effort:** S (the founder, plus one script).

### P0-3 The shipped build never runs in CI, and it depends on Next internals

CI runs `pnpm build`, not `build-site.sh`. So these four steps never run in CI:
- the copy out of `.next/server/app/*.html` and the `*.body` files (`build-site.sh:27-48`),
  which is undocumented Next layout;
- the defer regex on Next's exact script markup (`site-defer-scripts.mjs:15-16`);
- the social-card check;
- the API-address grep (`:69`).

The site is not `output: "export"` (`next.config.ts` has `/api` rewrites). Every site build
therefore compiles the whole workspace: 39 routes.

PR #108 (Next 16.4.2, a security fix) is exactly the change likely to break these steps. It
would surface only on the founder's laptop, at publish time.

**Fix:** run `bash scripts/build-site.sh` in CI and upload `out-site` as an artifact.

**Effort:** S.

## P1

### P1-1 `copy.ts` is 4,248 lines, with each Arabic line about 1,900 lines below its English twin

**Size.**
- English is at `copy.ts:452-2350`, Arabic at `2351-4247`.
- `copyShelf.ts` (928 lines) and `copyDocs.ts` (912) repeat the pattern.
- In total: 6,088 lines and 2,484 strings.

**Churn.** 25 commits have touched `copy.ts`. All four stacked PRs edit the same files:
`copy.ts`, `HomePage.tsx` and `home.css`. Trial merges are clean only because the PRs are
stacked; parallel PRs off `main` would collide.

**Naming.** `/chat` is the odd one out:
- `/chat` uses `copy.product` (`:436`) and `ProductPage.tsx`;
- the other pages use `copy.pages.<key>` (`:449`).

**Words outside the copy files.** The social-card `alt` text hard-codes "ALYR Shelf." and
the like in 7 route files.

**Fix:**
- Make one `_site/copy/<page>.ts` file per page, exporting `{ en, ar }` side by side.
- Turn `copy.ts` into a barrel that keeps `copy[locale]` working.
- Rename `product` to `pages.chat`.
- Move the `alt` names into copy.

**Effort:** M. It is mechanical, and `tsc` catches misses.

### P1-2 The types sync keys, not list lengths or optional fields

`const en: Copy` / `const ar: Copy` (`:452`, `:2351`) enforce the same keys and types. They
do not catch:
- a difference in any of the 54 array fields, such as a missing FAQ item;
- a missing one of the 39 optional fields;
- the `Partial<Record<…>>` rows.

The scan found:
- 0 length mismatches;
- 4 key mismatches, all an intended AR-only `demo.avatar` (`:84`).

So parity holds today by care, not by a check.

**Fix:** `scripts/site/copy-parity.mjs`. It fails on length or key differences, has an
allow list, and flags Arabic strings with no Arabic letters. The scratch version is 40 lines
and runs in under 1 s.

**Effort:** S.

### P1-3 No claims or banned-word lint

The AI-word grep is a manual step (`verify.md`).

The scan found:
- English: 0 hits for AI, "coming" or Payroll;
- English: 3 hits for "soon" (`:553, 925, 977`);
- Arabic: 3 hits for قريباً.

All six are on the pending-contact or offer-off paths, so they are legitimate only through
gating. A lint needs a gated-key allow list.

Identifiers sit among the words: 33 strings are identical in EN and AR (`booking_reminders`,
FAQ ids). So a naive check is noisy.

**Fix:** `copy-lint.mjs` with:
- the honesty list in EN and AR;
- a gated-key allow list;
- the retired sample names.

**Effort:** S.

### P1-4 A new product page means 10 steps, about 19 files, and a page list kept in two places

**Scale of the change.**
- The `alyr-site-page` checklist has 10 steps.
- `/shelf` is named in 19 files: 3 routes, `site.ts`, 3 copy files, 9 components, 2 CSS
  files and `build-site.sh`.
- ALY-205 (Shelf and Docs) touched 44 non-doc files, +5,519 lines.

**The page list is in two places.**
- `PATHS` and `PRODUCTS` drive the menu, footer and sitemap.
- `build-site.sh:25` keeps its own `pages=` list.
- Forget the second list and the page builds but is not published. Only the card loop
  notices.

**Fix:**
- Derive `pages=` from `site.ts`.
- Add a check that every `PRODUCTS` key has both routes, a card and copy.

**Effort:** S for the list, M for the check.

### P1-5 Deploy is manual and unpinned, with no previews
- Publishing is `npx wrangler deploy` on the founder's laptop (`docs/status.md:127`).
- `wrangler` is in no `package.json`, so `npx` resolves whatever version is current that
  day.
- There are no PR previews.
- `_headers` does work behind the Worker: HSTS, nosniff, X-Frame-Options and the OG type
  were checked live. Keep it.

**Fix:**
- Pin `wrangler`.
- Add an Action. Each PR runs `build-site.sh`, then `wrangler versions upload`, and posts
  the preview URL. `main` runs `wrangler versions deploy` behind a GitHub `production`
  environment that needs the founder's approval, so he still says yes to each publish.
- The founder creates a scoped API token for the secret.

**Effort:** M.

### P1-6 The verification tools sit outside `scripts/` and outside the repo
- **`shoot.mjs`** (307 lines) is in `docs/site-redesign/baseline/`. Ten skill and doc files
  cite that path.
- **Three headless-Edge drivers** do the same job: `browser-kit.mjs`, a copy inside
  `catalog-browser-check.mjs`, and `shoot.mjs`.
- **The probes are not committed** (`verify.md:75`). The 320 px, 44 px target, motion and
  style-diff probes ran from scripts outside the repo.
- **axe and Lighthouse** live in `C:\t\tools`, which `verify.md` calls "another session's
  folder".
- **The brotli static server** is not committed either.

**Fix:** a `scripts/site/` folder holding:
- `shoot.mjs` on `browser-kit`, with `--eval`;
- the probes;
- `serve.mjs`;
- `axe.mjs` and `lighthouse.mjs`, as pinned devDependencies.

**Effort:** M.

## P2

- **`build-site.sh:17` runs `rm -rf .next`.**
  - It deletes a running dev server's output. On Windows, locked files make the build fail
    halfway, hence "stop servers before rebuilding".
  - Fix: honour `ALYR_DIST_DIR`, defaulting to `.next-site`. S.
- **A non-default `distDir` rewrites `apps/web/tsconfig.json`** (observed here).
  - Fix: have the site scripts restore it. S.
- **Timings:**
  - `next build` 41 s (TypeScript 18.4 s, compile 6.9 s, 39 pages 2.8 s);
  - `tsc` 2 s, `lint` 16 s, `design-check` 1 s.
  - Speed is not the problem. The build prints 12 "AVIF not supported" warnings for
    `_site/report/*.avif`; fix those. S.
- **CSS:**
  - 7 global sheets, 2,433 lines, unscoped class names. `.top-nav a` once broke the menu.
  - 9 hard-coded breakpoints, including both `61.99rem` and `62rem`, and `47.99rem` beside
    the `48rem` token.
  - Fix: `design-check` rejects off-token breakpoints. S.
- **Dead code:**
  - No dead component files.
  - One unused key: `agent.flagged` (`copy.ts:589/2488`).
  - Fix: add an unused-key pass to the parity script. S.
- **About 20 untracked shot folders** clutter `git status`.
  - Fix: add `**/shots*/` to `.gitignore`. S.
- **Ports:**
  - 3100 is reserved for the demo. Ports 3101–3112 have all been taken by other sessions at
    once.
  - Fix: a `site:dev` that picks a free port and its own `distDir`. S.
- **Edge:**
  - Profiles need short paths, Git Bash needs `MSYS_NO_PATHCONV=1`, and stray processes
    re-attach.
  - Fix: default the profile to `C:\t\<script>-<pid>` and set the variable inside the
    script. S.
- **Tokens are good:** one JSON source, a generator, `--check` in CI, and `allow.json` with
  reasons. Keep as is.

## The five changes that would improve DX most

1. **A Cloudflare deploy from GitHub Actions** (M):
   - a preview URL on every PR;
   - production behind the founder's approval in GitHub;
   - a SHA stamp in every build;
   - `wrangler rollback` in the runbook.

   It fixes P0-1 and P1-5.
2. **Unblock CI and add a `site` job** (S, plus the founder's billing step): `build-site.sh`,
   parity, copy lint and the link check. This gates the PR stack and the Next upgrade.
3. **One `pnpm site:*` command set** (S–M): `site:dev`, `site:build`, `site:serve`,
   `site:shoot`, `site:probe`, `site:check` and `site:deploy`, with `wrangler` pinned. The
   skills then name commands, not paths.
4. **Move `shoot.mjs` and the probes into `scripts/site/`** (M). Put them on `browser-kit`,
   with axe and Lighthouse pinned. This ends the reliance on `C:\t\tools` and lets CI run
   the 320 px Arabic check and the Lighthouse budget.
5. **Split `copy.ts` per page, EN and AR side by side** (M). Keep a barrel, rename `/chat`
   to `pages.chat`, and derive `build-site.sh`'s page list from `site.ts`.
