# Heldat domain and public-surface runbook

Last verified: 2026-07-31

## Canonical hosts

| Host | Purpose | Current state |
|---|---|---|
| `heldat.app` | Public launch, legal, support, OAuth fallback and app-link paths | Live on Cloudflare Workers |
| `www.heldat.app` | Redirect-only alias to the apex | Live; permanent path-preserving redirect |
| `app.heldat.app` | Reserved for the production web app | Not published |
| `preview.heldat.app` | Optional protected prototype | Not published |

The existing web prototype is not a production surface. It remains local until
its API, account, sync and production-data paths are connected.
Both HTTP hosts permanently redirect to the canonical HTTPS apex while
preserving the path and query.

## Verified public paths

The following paths must return `200` over HTTPS:

- `/`
- `/privacy/`
- `/terms/`
- `/support/`
- `/delete-account/`
- `/security/`
- `/callback/`
- `/auth/callback/`
- `/join/`
- `/reset-password/`
- `/.well-known/security.txt`

Unknown routes must return `404`. Public responses must keep the configured CSP,
HSTS, `X-Content-Type-Options`, referrer and permissions-policy headers.

The account fallback pages preserve the incoming query string and hash when
constructing their allow-listed native links (`heldat://callback`,
`heldat://join`, and `heldat://reset-password`). They never auto-open the app.
These routes are served with `no-store`, `no-transform`, `no-referrer` and
`noindex` controls so one-time continuation parameters are not cached,
forwarded as referrers or measured by the edge-injected performance beacon.
Cloudflare's privacy-oriented performance beacon is the only third-party
script origin allowed by the public-site CSP.

## Authentication surface

- Supabase email and Google providers are enabled.
- The Google client uses `https://heldat.app` as its browser origin and the
  Supabase Auth callback as its only OAuth redirect.
- Google access is `External` and remains in `Testing`; the operator account
  is the sole test user.
- Requested Google scopes are limited to OpenID, email and basic profile.
- Heldat home, privacy and terms URLs are published in the Google consent
  configuration.
- Closed-pilot enrollment remains enforced by the database Auth hook. Enabling
  an identity provider does not open registration.

## Email routing

Cloudflare Email Routing forwards these receiving aliases to the verified
operator mailbox:

- `hello@heldat.app`
- `support@heldat.app`
- `privacy@heldat.app`
- `security@heldat.app`
- `legal@heldat.app`

The catch-all remains disabled. Email Routing is inbound forwarding only; it is
not transactional SMTP for Supabase Auth. Configure a dedicated sender before
opening email-based signup beyond the closed pilot.

## Registrar responsibilities

Spaceship remains the registrar and Cloudflare remains authoritative DNS.
Transferring the registration is unnecessary.

Owner checks:

1. Keep registrar auto-renew enabled and confirm the payment method.
2. Keep WHOIS privacy and transfer lock enabled.
3. Enable MFA on both registrar and Cloudflare accounts.
4. Keep registrant contact email current.
5. Complete DNSSEC as described below.

## DNSSEC completion

DNSSEC is complete only after all of these are true:

1. Enable DNSSEC for the zone in Cloudflare.
2. Copy the exact DS values generated by Cloudflare.
3. Add those exact DS values in Spaceship Advanced DNS.
4. Wait for delegation propagation.
5. Verify that public resolvers return a DS record for `heldat.app`.

Never invent or reuse DS values from another zone. If validation fails, compare
the registrar DS values with Cloudflare before changing nameservers.

## `www` configuration

The canonical redirect is configured without an origin server:

- a proxied `www` DNS record reaches Cloudflare;
- `www.heldat.app/*` is a normal zone route in
  `heldat-site/wrangler.jsonc`;
- the Worker returns `308` to the same path and query on
  `https://heldat.app`.

Do not use a Worker custom-domain binding while the same hostname already has
conflicting DNS records; use a normal zone route.

## Deployment and rollback

From the repository root:

```powershell
npm run check:site
npm run deploy:production --workspace=@heldat/site
```

Before deployment:

- confirm tests pass;
- confirm no association template with placeholder platform identities is
  present under `heldat-site/public/.well-known`;
- confirm legal and support contacts are unchanged intentionally.

Rollback uses the last known-good Worker version in the Cloudflare dashboard.
After rollback, probe every verified public path and inspect response headers.
Unversioned public scripts and styles use bounded revalidation rather than an
immutable one-year browser cache. The content-hashed account-continuation
script is always served `no-store`.

## App association publication gates

Publish `/.well-known/assetlinks.json` only after the Android package and every
accepted signing-certificate SHA-256 fingerprint are confirmed. Add the Google
Play App Signing fingerprint when Play enrollment exists.

Publish `/.well-known/apple-app-site-association` only after the Apple Team ID
and bundle ID are confirmed. Placeholder or empty association files stay
outside the public directory because mobile platforms cache them.
